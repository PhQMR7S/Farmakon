## 6. الوصولية وRTL ولوحة المفاتيح

[الدليل الآلي المحلي](evidence/F00.7-ACCESSIBILITY.json)، باستخدام `@axe-core/playwright 4.10.2` / `axe-core 4.10.3`، وقواعد WCAG 2/2.1/2.2 A/AA المتاحة. قبل التعديل: 12 scan على 390 و1280px دون مخالفات axe. بعد التعديل: 28 scan على **360/390/768/1280px**، دخول/لوحة/كورسات/مكتبة/أسئلة/امتحان ووضع داكن للامتحان، دون مخالفات axe أو horizontal overflow في هذه الحالات.

44 Browser E2E = 32 سابقة + 12 جديدة، موزعة على Desktop وAndroid viewport، تشمل:

- skip link وتركيز المحتوى، inert للقائمة المغلقة، حصر Tab وShift+Tab، Escape وإرجاع التركيز، وحالة aria-expanded.
- modal له اسم، تركيز أول عنصر وحصره وإعادته للمشغل، وفلاتر native بأسماء وصولية ولوحة مفاتيح.
- Labels الدخول، إعلان حالات الحفظ، فشل الحفظ دون نجاح كاذب، تحذير البيانات القديمة وإعادة المحاولة، الانقطاع والاستئناف.
- عداد `role=timer` مع `aria-live=off`، فلا يعلن كل ثانية. اختيار الإجابة يدعم aria-pressed.
- RTL ووسم المقاطع الإنجليزية الموجودة بـlang=en/dir=ltr. لا نظام ترجمة جديد أو واجهة إنجليزية كاملة.
- تكبير نص 200% في الحالات المقاسة، وإطار focus مرئي، وعدم تغيير هوية Farmakon أو إعادة تصميمها.

**فجوة Console/الخط:** في التدقيق المحلي ظهرت رسائل `ERR_EMPTY_RESPONSE` و`Couldn't load preload assets` أثناء تحميل موارد. CSS ما زال يحتوي `@import` خارجياً لـGoogle Fonts. هذا اعتماد غير مغلق؛ لا يجوز إعلان console نظيفة. عداد `consoleErrors` في دليل after يجمع warnings/errors وpageerror تراكمياً، ووصل 16 داخل كل context بعد تكرار الفحوص؛ before كان يعد pageerror فقط، لذا لا تجوز مقارنة العدادين كارتفاع أخطاء جديد. سبب كل رسالة لم يصنف مستقلاً. الاستضافة المحلية للخط كانت مقترحة ولم تنفذ؛ تم إيقاف التوسع لصالح تسليم النتائج المثبتة.

**غير مغلق:** قارئ شاشة فعلي، Android عتادي، iOS/Safari/Firefox، جميع الحالات الإدارية والألوان غير المعروضة، وتدقيق WCAG 2.2 AA شامل. النجاح الآلي لا يساوي شهادة امتثال.

## 7. قاعدة البيانات وMigration والتوافق

الملف `supabase/migrations/20261027113817_f007_student_record_lookup.sql` مولد بـSupabase CLI 2.81.3، ويضيف فهرساً فقط على `(data::jsonb->>'userId'),kind,created DESC,id DESC`. لا تعديل صفوف أو RLS أو grants أو جلسات أو درجات أو احتفاظ.

**لم يُطبق في Staging أو Production.** مراجعة metadata في Staging وجدت فقط `records_pkey/records_kind/records_course`. الأرقام indexed أعلاه تتطلب الكود والفهرس المختبرين معاً؛ ليست نتيجة قاعدة Staging الحالية.

قبل أي تطبيق حي لاحق: تحقق JSON القديم، تقدير الحجم ووقت البناء، واختيار نافذة/بناء concurrent معتمد. CREATE INDEX العادي قد يحجز الكتابات أثناء البناء؛ لا يطبق تلقائياً من التطبيق. PostgreSQL المعزولة اختبرت migration وRLS والخصوصية والتزامن والنسخ/الاستعادة بعد وجودها.

باقي القيود: الكتالوج وactivity وبعض قوائم الإدارة وتاريخ الطالب ما زالت بلا pagination شاملة. أُزيل تحميل بيانات الطلاب الآخرين، ولم نقطع قوائم الطالب بصمت. النتائج المعروضة تحتفظ بحد 50 نتيجة مصرح بها كما في F00.6. snapshot الأسئلة، الحجب بعد السحب، والـlegacy grace لم تتغير.

## 8. الاعتمادية والمراقبة

- اختبارات DB/Storage outage تؤكد رسائل عامة دون تسريب قيمة حساسة اصطناعية في response أو log.
- اختبار المحول يؤكد release قبل backoff، خمس محاولات بحد أقصى، وعدم إعادة COMMIT غير المتيقن. اختبار PG يتأكد من rollback واستعادة اتصال صالح وعودة pool إلى idle دون waiting.
- Storage يميز missing عن unavailable، ويلغي جسم الرد الفاشل وينقل إلغاء العميل. مهلة الترويسات لا تشمل إصدار الرابط في SDK ولا تعمم على Auth وكل استعلامات DB.
- تبقى مهلة connection acquisition الحالية 10s وpool idle 10s. لا statement timeout جديد أو deadline عام للـSQL/Auth أضيف؛ سياسة تلك الحدود تحتاج قياساً واعتماداً، خصوصاً lock waits والأعطال الطويلة.

مؤشرات مقترحة دون تفعيل خدمة أو مخزن دائم: P50/P95 حسب route/action، 5xx و503/429، زمن وانتظار pool، 40001/retry exhaustion، إخفاق حفظ الإجابة وStorage، زمن Auth وأخطاء التجديد. تُسجل وسوم ثابتة أو معرف طلب عشوائي عند اعتمادها، دون بريد أو userId أو answers أو query params أو Cookies/Tokens. حد الإيقاف الصفري للاختبار لا يحدد SLO إنتاجياً؛ إنذارات الإنتاج وحدودها تتطلب baseline حياً معتمداً.
