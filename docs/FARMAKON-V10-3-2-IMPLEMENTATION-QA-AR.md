# Farmakon V10.3.2 — سجل التنفيذ والمراجعة الآمنة

**التاريخ:** 3 نوفمبر 2026
**المستودع:** PhQMR7S/Farmakon
**الفرع:** feature/farmakon-v10-3-2-course-details-2026-11-03
**قاعدة البناء:** Draft PR #25، الذي يعتمد على PR #24 وV10.3/V10.2 وV10.1.
**الإنتاج:** غير معدّل، ولا دمج إلى main.

## ما نُفِّذ فعلياً
1. Course Details مكوّن مستقل في `app/components/course-details.tsx`، يعمل داخل منصة الطالب ويستعمل غلاف المالك أو أيقونة المجال المعتمدة.
2. إظهار عنوان ووصف الكورس، المرحلة، المجال، السعر بالدينار، مدة الاشتراك، عدد الوحدات والمحاضرات المنشورة، وإجمالي وقت المحاضرات المحدد من صاحب الكورس.
3. تبويبا نظرة عامة/المنهج، ووحدات يمكن توسيعها وطيها، ومحاضرات مرتبة بحقل `order` و`module` الموجودين حالياً؛ مسميات فارغة تعود إلى «محاضرات الكورس».
4. حالات الحساب `active/pending/expired/free` تُشتق من صفوف `enrollments` وطلبات `orders` التي يعيدها API لهوية المستخدم. لا تَمنح مجانية السعر حق فتح الملفات المحمية دون إذن.
5. الضغط على المحاضرات غير المقفلة فقط، مع استمرار الحارس الخادمي الموجود في API عند تشغيل/حفظ المادة. طلب الاشتراك وتفعيل الكود يعيدان استخدام أحداث الـModal الموجودة ولا توجد بوابة دفع جديدة.
6. دمج في `app/platform.tsx` مع الإبقاء على تشغيل المحاضرة الحالية دون إعادة كتابة المشغّل؛ الحفاظ على لوحة المالك كما هي.
7. استبدال Placeholder تفاصيل الكورس بمعاينة مشتركة `CourseDetails`، وإظهار تنبيه أن المحتوى توضيحي بلا تشغيل حقيقي أو مدفوعات.
8. CSS معزول لأحجام الهاتف/التابلت/الكمبيوتر، مع RTL/LTR-ready وتركيز لوحة المفاتيح وتقليل الحركة.
9. اختبارات `scripts/test-course-details.mjs` لـ11 مجموعة وحزمة prebuild؛ Workflow `v10-3-2-quality.yml` يستخدم `npm ci --ignore-scripts`, `npm run typecheck`, `npm run build`، بدون أسرار أو اتصال بقاعدة البيانات.

## التحقق الحالي
- تم إنشاء الملفات والتعديلات في GitHub، وفتح Draft PR مستقلة للمراجعة.
- لم تُثبت نتيجة نجاح CI/Bundler للنسخة الكاملة حتى وقت هذا التقرير. **لا يجوز احتساب الـ11 مجموعة اختبار على أنها PASS إلى أن يظهر سجل تشغيل حقيقي.**
- Vercel أبقى آخر Build سابق للاختبار، وأظهر قيود حد الإنشاء في الخطة المجانية عند تحديثات هذا اليوم. لذلك **لا يوجد رابط معاينة متحقق منه لهذه المرحلة الجديدة بعد**.
- أُضيف متغير `FARMAKON_PREVIEW_READ_ONLY=1` إلى فرع V10.3.2 ضمن هدف preview فقط؛ production untouched.

## فحص Staging الآمن — بدون قراءات بيانات طلاب
- مشروع `Farmakon-Staging` مستقل ومعرّفه `qfzharpouemueipsrduv` والحالة التي تعيدها Supabase ACTIVE_HEALTHY.
- إعداد `DATABASE_URL` المشفّر في فرع `feature/farmakon-otp-staging-validation-2026-11-01` موجود، لكن فحص احتواء مرجع مشروع Staging **فشل**. لم يُعرَض الرابط أو كلمة مروره، ولم يُعدَّل.
- يجب إدخال Database Transaction Pooler URL الصحيح من مشروع Staging **في إعدادات Vercel مباشرة** مع SSL والـrole المناسب، وعدم نسخه في GitHub أو الدردشة.
- لا تعطل حارس `STAGING_DATABASE_ISOLATION_REQUIRED` ولا تحول واجهة طالب معاينة إلى البيانات الحقيقية حتى تجتاز `/api/health` في فرع Staging ثم E2E بأشخاص تجريبيين مصرح بهم.

## بوابات القبول قبل الاعتماد
1. CI: TypeScript/build و34 مجموعة سابقة + 11 جديدة دون أخطاء. 
2. الهواتف: قياسات 320/360/390/430/768/1366 مع عدم حجب المحتوى، وتبويبات ونوافذ فعالة.
3. اختبار حساب طالب لديه اشتراك/منتهٍ/طلب معلق/بدون اشتراك، ومحاضرات free/locked/draft ومراجعة طلب الاشتراك/تفعيل الكود ضد Staging المعزولة فقط.
4. اختبار صلاحيات API لجميع المسارات، لا فتح مباشر لملف مدفوع ولا روابط Drive خاصة للعموم؛ أي مشكلة تُعالج قبل النشر.
5. مراجعة المالك، ثم إصدار متسلسل PR #21→#22→#23→#24→#25→#26 بعد إغلاق جميع البوابات.
