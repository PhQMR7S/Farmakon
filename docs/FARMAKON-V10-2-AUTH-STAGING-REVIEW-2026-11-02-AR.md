# Farmakon V10.2 — اختبار التسجيل الحقيقي + المعاينة النهائية
التاريخ: 2026-11-02
المستودع: `PhQMR7S/Farmakon`
الفرع: `feature/farmakon-otp-staging-validation-2026-11-01`
نسخة احتياطية قبل التعديلات: `backup/farmakon-otp-staging-before-v102-2026-11-02`

## الهدف المنفذ
- إزالة شاشة المقارنة بثلاثة تصاميم من مسار تجربة الحساب. المعاينة النهائية تعتمد **التصميم المتوازن** حصراً.
- الاحتفاظ بواجهة الدخول والتسجيل المعتمدة دون تغيير شكلها، مع البريد + رمز OTP من ستة أرقام واسترجاع كلمة المرور.
- بعد التأكيد، الانتقال تلقائياً إلى الجذر `/` لفتح معاينة V10.2 باسم الطالب الحقيقي من `auth.users.user_metadata.name` في مشروع **Farmakon-Staging**.
- ظهور الهيدر الأصلي، تبويبات التعلّم الخمسة، الترحيب المتجدد عند تسجيل دخول جديد، الأيقونات ثلاثية الأبعاد، أقسام التعلّم الثمانية، والتفاعل باللمس.
- لا تُحمّل بيانات المنصة الأصلية أو اشتراكاتها. هذه **تجربة تصميم مصادق عليها**، وليست اختباراً نهائياً لحفظ تقدم الكورسات.

## العزل المثبت
- مشروع Supabase-Staging: `qfzharpouemueipsrduv` مختلف عن مشروع الإنتاج `zviqtacbsprewyxrmpbb`.
- تم فحص متغير `NEXT_PUBLIC_SUPABASE_URL` المرتبط بفرع Staging؛ يشير إلى مشروع Staging الصحيح.
- متغير `FARMAKON_AUTH_STAGING_ONLY=1` على فرع Staging في Vercel.
- قُيدت صفحة جذر الطالب وواجهات Auth بـ`VERCEL_ENV=preview` ومرجع Staging الصحيح.
- فحص `DATABASE_URL` في `lib/database.ts` يمنع أي استخدام لقاعدة بيانات لا تحمل المرجع الخاص بـStaging؛ كما يمنع التشغيل خارج Preview.
- **اكتُشف** أن `DATABASE_URL` الحالي في متغيرات Staging لم يطابق مرجع المشروع المنفصل. لذلك فشل `GET /api/health` بالرسالة `STAGING_DATABASE_ISOLATION_REQUIRED`. لم نعطّل فحص الأمان لتجاوز المشكلة.
- نتيجة لذلك، عُرضت للطالب نسخة V10.2 المصادق عليها من `StudentStagingReview` وتعتمد على بيانات اسم المصادق فقط، **بدون API للكورسات أو حفظ التقدم**. تُعرض ملاحظة واضحة داخل المعاينة.

## اختبارات منجزة
- بناء Next.js وTypeScript: نجح في Vercel بعد تصحيح مسارات مكونات Staging.
- `PASS 7 Learning Center logic groups` في سجل build.
- `GET /farmakon-auth.html`: HTTP 200، واجهة الدخول الأصلية، التسجيل بخطوتين، رمز التحقق والاستعادة.
- `GET /` بدون جلسة: يحوّل إلى واجهة الدخول ولا يعرض بيانات الطالب.
- `GET /v10-preview/learning` على فرع Staging: 404؛ لا تعرض شاشة المقارنة القديمة.
- إنشاء الحساب مع صندوق بريد حقيقي، إرسال الكود وتأكيده، متابعة صفحة الطالب داخل جلسة مصادقة: **اختبار يدوي للمستخدم ما زال مطلوباً**.
- `GET /api/health`: HTTP 503، بسبب فشل حماية ربط قاعدة Staging، **ليس ناجحاً**.
- لم تُنفَّذ تغييرات في `main` أو إنتاج Supabase، ولم تُعدل SMTP أو قوالب الرسائل.

## رابط دخول الطالب التجريبي
المسار: `/farmakon-auth.html` في آخر Deployment READY لفرع Staging. الرابط المحمي يتطلب مشاركة Vercel صالحة ولا يجب حفظ رمز المشاركة داخل المستودع.

## خطوات التحقق بحساب الطالب
1. افتح رابط المعاينة المشارك، اختر إنشاء حساب وأدخل بريدك الشخصي/التجريبي.
2. أكمل المرحلة الدراسية والجامعة والمحافظة، ثم أرسل طلب التسجيل.
3. أدخل رمز البريد ذي 6 أرقام (بدون إرساله لأي شخص).
4. يجب أن تتحول إلى صفحة «مركز التعلّم» وتظهر باسمك الحقيقي.
5. جرّب الهيدر والتنقل السفلي وأقسام التعلّم وإغلاق اللوحات.
6. جرّب تسجيل الخروج، ثم الدخول مرة ثانية، ويُفضّل أن تتغير الرسالة التحفيزية مع استمرار ثباتها خلال نفس الجلسة.
7. لا تعتبر الأرقام والاشتراكات ومتابعة الفيديو داخل هذه المعاينة نتيجة اختبارات حقيقية؛ هي حالات فارغة مقصودة.

## قبل إطلاق الكورسات والتقدم على Staging
- يلزم وضع **DATABASE_URL خاص بـFarmakon-Staging** من Supabase Dashboard → Connect → Transaction Pooler، وتهيئة role/grants/SSL بما يطابق المشروع، وإدخاله مباشرة في متغير Vercel Preview للفرع المستهدف. لا يُشارك الرابط أو كلمة مروره في المحادثة أو المستودع.
- يجب أن يعرض `GET /api/health` نتيجة `database:true` أولاً؛ بعدها يمكن تحويل `app/page.tsx` إلى مكوّن `Farmakon` الحقيقي الموجود ومختبر البناء، ثم اختبار صلاحيات/تقدم الطالب ضمن قاعدة Staging فقط.
- دمج `V10.1` و`V10.2` للإنتاج لا يزال ممنوعاً حتى اجتياز الفحوصات النهائية.
